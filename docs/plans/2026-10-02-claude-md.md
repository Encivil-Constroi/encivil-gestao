# Plano — Reescrita do CLAUDE.md (≤ 200 linhas)

**Objetivo:** um `CLAUDE.md` que permita a qualquer IA, sem contexto prévio, entender o ENCIVIL Gestão, trabalhar sem
alucinar e respeitar as regras críticas (RLS, stock, migrations, segredos).

**Decisões (tomadas no brainstorming, sem perguntas):**
- Um único ficheiro, ≤ 200 linhas, só factos verificados no repositório; o que é detalhe aponta para `docs/`.
- Corrigir divergências do ficheiro antigo (`src/components` não existe → `src/app/components/ui`; variável
  `VITE_SUPABASE_PUBLISHABLE_KEY`; módulos `colaboradores`/`frota` na matriz de escrita; migrations aplicadas à mão no SQL Editor).
- `AGENTS.md` mantém-se (aponta para o `CLAUDE.md`, que vence em conflito).

## Tarefas
1. **T1 — Redigir** o novo `CLAUDE.md` (coordenador, a partir da exploração do repositório).
2. **T2 — Auditoria factual** (agente A, paralelo): confirmar cada caminho, comando, nome de RPC/função/tabela/papel citado.
3. **T3 — Teste a frio** (agente B, paralelo): agente sem contexto lê só o `CLAUDE.md` e responde a 12 perguntas sobre o projeto;
   respostas erradas ou "não sei" indicam lacunas.
4. **T4 — Comandos** (coordenador, paralelo): `npm run typecheck`, `npm test`, `npm run build` a verde.
5. **T5 — Frontend** (agent-browser, local): `npm run dev`, abrir `/login` e uma rota protegida, confirmar que a app arranca sem erros de consola.
6. **T6 — Corrigir** o que T2/T3 apontarem; repetir só o que mudou. Sem commit (o utilizador decide).

**Critério de conclusão:** `wc -l CLAUDE.md` ≤ 200; auditoria sem afirmações falsas; teste a frio ≥ 11/12 certas; typecheck, testes e build a verde.

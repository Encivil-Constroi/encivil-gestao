# ADR-009 — Manter PWA React em vez de migrar para Flutter + NestJS

**Data:** 2026-07-30  
**Estado:** Aceite

---

## Contexto

A especificação v3.0 (30-07-2026) propõe Flutter + NestJS/FastAPI + PowerSync + MinIO para a expansão do sistema a ERP completo. O sistema actual é React 18 PWA + Supabase, em produção com utilizadores reais.

## Decisão

Manter o stack React + Supabase e expandir incrementalmente os módulos nele. Não migrar para Flutter.

## Consequências

**Positivas:**
- Zero ruptura — sistema em produção continua a funcionar durante o desenvolvimento
- Schema PostgreSQL 100% reutilizável se Flutter for adoptado no futuro
- PostGIS disponível no Supabase — geofences implementáveis sem mudar stack
- PWA instala no home screen; updates chegam sem revisão de app store
- 22 semanas de entrega incremental vs 3-4 meses para MVP Flutter sem nada em produção

**Negativas:**
- Sem deteção de mock GPS (fake location apps) — risco marginal em estaleiro pequeno
- PowerSync mais robusto que `useOfflineQueue` — aceite dado o volume actual

## Condição de reavaliação

Se houver evidência documentada de fraude de GPS em produção, avaliar Flutter exclusivamente para o ecrã de picagem, mantendo o resto em React.

## Alternativa rejeitada

Flutter + NestJS/FastAPI + PowerSync + MinIO: correcto a longo prazo, mas custo de transição não justificado com utilizadores reais no sistema actual.
